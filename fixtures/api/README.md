# Réponses d'API pour les tests

Réponses **construites** d'après la documentation publique des API (forme des champs), pas des enregistrements réels, sauf `commons-search.json`. Elles servent à tester l'analyse des réponses sans appel réseau.

- `commons-search.json` : réponse **réelle** de `GET https://commons.wikimedia.org/w/api.php`, enregistrée le 19/11/2026 par un seul appel manuel (`action=query`, `formatversion=2`, `generator=search`, `gsrsearch=high-speed train filetype:bitmap`, `gsrnamespace=6`, `gsrlimit=10`, `prop=imageinfo`, `iiprop=url|extmetadata|mime|size`, `iiurlwidth=1600`, métadonnées filtrées). Formes observées : `query.pages[]` dans le désordre (rang dans `index`) ; vignette sur `thumb.wikimedia.org` (`…/1920px-…` alors que `thumbwidth` vaut 1600), original sur `upload.wikimedia.org`, tous deux suivis de paramètres `utm_*` ; quand l'original est plus étroit que 1600 px, `thumburl` est l'original et `thumbwidth`/`thumbheight` sont agrandis ; `Artist` est du HTML ; `LicenseUrl` parfois en `http://`. Le meilleur résultat est le TGV (JPEG, CC BY-SA 3.0) ; on y trouve aussi des portraits, un « line scan » panoramique, un schéma presque carré (CC0) et des PNG.

- `commons-debate-iowa.json` et `commons-spain-parliament.json` : réponses **réelles** de la même API, enregistrées le 20/11/2026 (un appel chacune, agent `DailyBrief/1.0 (personal news digest)`), avec les paramètres actuels de `commonsSearchUrl` (`gsrlimit=20`, `iiurlwidth=1280`, métadonnées `ObjectName`, `ImageDescription` et `Categories` en plus). `television studio cameras debate` ne renvoie qu'un fichier : les pancartes de campagne de Roxanne Conlin à Des Moines (Iowa, 2010), dont la description parle d'un débat télévisé, celle qui a illustré un débat Sánchez–Feijóo ; il doit être refusé. `spain parliament building madrid` renvoie le Palais des Cortès, des lions du Congrès, des portraits d'élus (catégorie à leur nom ou « Politicians of Spain »), une ambassade d'Irlande, des cartes de localisation et une stéréophotographie du Rijksmuseum (catégorie Amsterdam). Les catégories arrivent dans `extmetadata.Categories` (séparées par `|`, catégories de maintenance comprises) ; `ObjectName` peut contenir du HTML.
- `thenewsapi-top.json` : `GET https://api.thenewsapi.com/v1/news/top` (documentation TheNewsAPI : `meta` et `data[]` avec `uuid`, `title`, `description`, `keywords`, `snippet`, `url`, `image_url`, `language`, `published_at`, `source`, `categories`, `relevance_score`, `locale`). Le troisième article n'a pas d'URL : il doit être ignoré.
- `thenewsapi-similar.json` : `GET https://api.thenewsapi.com/v1/news/similar/{uuid}`, même forme, `relevance_score` numérique.
- `exa-search.json` : `POST https://api.exa.ai/search` (documentation Exa : `results[]` avec `id`, `title`, `url`, `publishedDate`, `author`, `text`). Le résultat de lemonde.fr porte un texte qui doit être écarté (R1) ; le dernier résultat est mal formé.
- `webz-news-lite.json` : `GET https://api.webz.io/newsApiLite` (forme des `posts[]` de Webz.io : `thread`, `uuid`, `url`, `published`, `title`, `text`, `language` en toutes lettres). Le texte d'elpais.com doit être écarté (R1) ; un post est hors fenêtre, un autre mal formé. Le champ `next` contient un faux jeton.
- `rss-euronews-fr.xml` et `atom-elsalto.xml` : flux RSS 2.0 et Atom construits d'après la forme des flux Euronews et El Salto (CDATA, entités, `guid` sans `link`, lien `alternate`, article hors liste blanche, hors fenêtre ou sans lien).
- `article-euronews.html` : page d'article construite (menu, script, article, encadré, pied de page) pour l'extraction du texte intégral.
- `tts-synthesize.json` : `POST https://texttospeech.googleapis.com/v1/text:synthesize` (documentation Google Cloud Text-to-Speech v1 : `SynthesizeSpeechResponse`, champ `audioContent` en base64). L'audio est **synthétique** : une trame d'information « Xing » puis trois trames MPEG-2 couche III de silence (24 kHz, 32 kb/s, mono), fabriquées par `pipeline/test/audio/mp3.ts`, pas une vraie voix.
- `tts-voices.json` : `GET https://texttospeech.googleapis.com/v1/voices?languageCode=fr-FR` (documentation v1 : `voices[]` avec `languageCodes`, `name`, `ssmlGender`, `naturalSampleRateHertz`). Les noms suivent la forme `<langue>-Chirp3-HD-<nom>` de la documentation, **à confirmer par un vrai appel** ; la liste mêle des voix Chirp 3 HD, une voix « Chirp-HD » (autre famille), Neural2, WaveNet et une voix fr-CA, pour tester le filtre.
